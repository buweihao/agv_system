# Skill 03: 纯静态地图校验器

## 1. 目标

建立一个纯算法、无 UI、无调度、无车辆控制依赖的地图静态校验器，用于发布草稿或导入地图前拦截明显错误。

校验器只判断静态地图数据一致性，不判断路径是否可达，不做路径规划，不做交通死锁分析。

## 2. 第一红线

- 禁止调用 `IPathPlanner` 或旧 `IPathPlanningService`。
- 禁止判断“某点是否可达”。
- 禁止判断“车辆能否到达某点”。
- 禁止读取车辆实时状态、点位占用、交通锁、预约信息。
- 禁止在校验结果中输出路径规划建议。

## 3. 推荐接口形态

可以新增纯静态校验器类，例如：

```csharp
MapValidationResultDto ValidateSnapshot(
    MapSnapshotDto snapshot,
    MapStaticReferenceContext references);
```

`MapStaticReferenceContext` 只承载静态外部引用，例如：

- 已配置充电桩引用的节点 ID。
- 已配置车辆默认待机点和默认充电点。
- 厂商点位映射要求。

这些引用由 `IMapManagementService.ValidateDraftAsync` 组装后传入，校验器本身不查数据库。

## 4. P0 错误

这些错误必须阻止发布：

- `MapId` 为空。
- 区域 ID 为空或重复。
- `NodeId` 为空或重复。
- `EdgeId` 为空或重复。
- 边的 `FromNodeId` 或 `ToNodeId` 不存在。
- 边的起点和终点相同。
- 节点或路线填写了区域 ID，但区域 ID 不存在。
- 点位容量、区域容量为负数。
- 厂商点位映射指向不存在的系统节点。
- 同一厂商下 `VendorNodeCode` 重复。
- 导入 payload 或草稿快照中出现 `IsOccupied`、`IsLocked`、`ReservationId` 等运行态字段。
- 静态充电桩引用的节点不存在。
- 静态充电桩引用的节点不是充电类型。

## 5. P1 警告

这些只提示，不默认阻止发布：

- 不同节点坐标完全相同，或距离低于配置阈值。
- 节点没有任何边引用。注意：只能描述为“孤立静态节点”，不要写“永远不可达”。
- 非终端类节点只有入边没有出边。注意：只能描述为“拓扑可能不完整”，不要写“死胡同不可达”。
- 边距离为 0 或未配置。
- 节点或边缺少名称、区域、编码等可维护性信息。
- 区域没有任何节点或路线引用。
- 车辆通行约束为空但路线或点位类型看起来需要限制，只提示维护人员确认。
- 同一系统点位存在多个厂商映射时，只提示确认；同一厂商编码重复仍是 P0。

## 6. 输出标准

每条校验消息应包含：

- `Level`
- `ElementType`
- `ElementId`
- `Message`
- 可选 `Code`

如果当前 `MapValidationResultDto` 只有字符串列表，允许先复用字符串，但建议在不破坏契约的前提下新增结构化消息 DTO。

## 7. 注释要求

校验器类顶部必须注明：本类只做静态结构一致性校验，不做路径规划、可达性、交通资源或车辆状态判断。
