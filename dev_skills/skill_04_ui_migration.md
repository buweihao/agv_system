# Skill 04: 系统设置地图 UI 草稿化迁移

## 1. 目标

迁移 `SystemConfigModule` 中的地图配置 UI，使它从“直接编辑数据库实体”变为“编辑地图草稿”。UI 只通过 `IMapManagementService` 保存、校验、发布地图。

本步骤应尽量复用现有画布编辑能力，但改变 ViewModel 的数据来源和保存语义。

## 2. 第一红线

- `MapConfigViewModel` 不再直接保存 `IMapRepository`。
- UI 保存按钮不能直接改变当前运行地图。
- 导入按钮不能直接覆盖当前运行地图。
- UI 不调用 `IMapService` 做保存或发布。
- UI 不引入路径规划、交通管制、点位占用、车辆控制能力。

## 3. 初始化流程

初始化必须有明确草稿来源：

1. 如果存在用户选择或最近草稿，则调用 `GetDraftAsync(draftId)`。
2. 如果没有草稿，则调用 `CreateDraftAsync`，从当前运行图或空模板创建新草稿。
3. 将 `MapSnapshotDto` 映射为 UI 编辑集合。
4. UI 显示当前 `DraftId`、地图名称、草稿更新时间。

不要调用无参数 `GetDraftAsync()`，因为当前契约要求 `DraftId`。

## 4. UI 语义调整

- “保存”改为“保存草稿”。
- 新增“发布地图”。
- 新增或保留“校验地图”。
- “导入 JSON”改为“导入为草稿”。
- “导出 JSON”导出当前草稿或选定版本，由 UI 选择文件路径，服务只处理 payload。
- 版本列表显示 `MapVersionDto`。
- 回滚按钮必须二次确认，并提示这是运行地图切换操作。

## 5. 必须覆盖的编辑对象

UI 迁移完成后，地图编辑与管理至少要能维护这些静态配置：

- 点位：类型、位置、所属区域、容量、启用状态、厂商映射。
- 路线：起点、终点、单向/双向、距离、启用状态、车辆通行约束。
- 区域：名称、类型、边界或范围、容量、启用状态。
- 地图：草稿信息、校验结果、发布备注、版本列表、导入导出 payload。

推荐页面结构：

- 顶部工具条：新建草稿、保存草稿、校验、发布、导入、导出。
- 中间区域：地图画布和表格/列表视图切换。
- 右侧属性面板：编辑当前选中的点位、路线、区域或厂商映射。
- 底部或侧栏：校验消息、版本列表、回滚入口。

## 6. 画布编辑注意事项

现有 code-behind 可继续承担拖拽、缩放、框选、键盘快捷键等纯交互逻辑。不要为了“纯 MVVM”强行搬走复杂鼠标逻辑。

业务动作必须留在 ViewModel：

- 保存草稿
- 校验草稿
- 发布草稿
- 导入导出 payload
- 版本列表
- 回滚

## 7. 去除锁概念

现有 `EditorEdgeVm.IsLocked` 容易被误解为交通锁或运行态锁。

推荐处理：

- 删除编辑器里的 `IsLocked` 概念。
- 如果需要表达静态封闭，用 `MapEdgeDto.Enabled = false` 或静态 `Direction`/`EdgeType` 表达。
- UI 文案使用“启用/禁用”“封闭方向”，不要使用“锁定”“占用”“预约”。

## 8. DTO 与 UI 映射

UI 可以继续使用内部编辑 VM，但保存草稿前必须转换为 `MapSnapshotDto`。

转换规则：

- UI 节点 -> `MapNodeDto`
- UI 边 -> `MapEdgeDto`
- UI 区域 -> `MapAreaDto`
- UI 厂商映射/别名 -> `VendorNodeMappingDto`

旧 `Core.Models.MapNode/MapEdge` 只能在迁移过渡期作为 UI 内部兼容对象，不允许继续作为服务边界传出。

## 9. 注释要求

在 ViewModel 的保存、发布、回滚方法上写简洁中文注释，明确：

- 保存草稿不影响生产运行图。
- 发布地图会切换当前运行图。
- 回滚地图会触发运行图刷新事件。
